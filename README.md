# SegFormer на CamVid — семантическая сегментация трансформером

Дообучение компактного трансформера **SegFormer-B0** на датасете **CamVid** и
сравнение с ранее обученной свёрточной моделью (DeepLabV3-ResNet50) на той же выборке.
Переход от ViT-классификации к попиксельному предсказанию.

Материалы: [статья SegFormer](https://arxiv.org/abs/2105.15203) ·
[туториал HuggingFace по сегментации](https://huggingface.co/docs/transformers/tasks/semantic_segmentation)

---

## Задача 1. Что предлагают авторы SegFormer

SegFormer объединяет иерархический трансформерный энкодер с предельно простым
декодером из MLP-слоёв. Вся «тяжесть» вынесена в энкодер, а декодер намеренно
облегчён — за счёт этого модель одновременно точная, быстрая и устойчивая к
искажениям. Три ключевые идеи:

### Иерархический энкодер (Mix Transformer, MiT)

Обычный ViT делит изображение на патчи один раз и дальше работает на одном
низком разрешении. Энкодер SegFormer устроен в **4 стадии**: после каждой карта
признаков уменьшается по высоте/ширине, но углубляется по каналам — как в
свёрточных сетях. Два отличия от ViT:

- **Перекрывающиеся патчи** (overlapping patch merging, параметры K/S/P) — чтобы
  сохранять непрерывность на границах патчей.
- **Mix-FFN вместо позиционного кодирования** — информацию о положении даёт
  свёртка 3×3 внутри FFN. Поэтому модель не теряет точность, когда разрешение на
  тесте отличается от обучающего (у ViT с фиксированным PE здесь просадка).

Дополнительно энкодер использует *efficient self-attention* с коэффициентом
сокращения R, снижающим сложность внимания с O(N²) до O(N²/R).

### Признаки нескольких масштабов (multi-scale)

Благодаря 4 стадиям энкодер выдаёт карты признаков разрешением **1/4, 1/8, 1/16,
1/32** от исходного. Мелкомасштабные (1/4) хранят тонкие детали и границы
объектов, крупномасштабные (1/32) — общий контекст сцены. Для сегментации нужно
и то, и другое одновременно, а не одна карта, как у ViT.

### Лёгкий декодер (All-MLP)

Декодер собирает четыре карты в маску за 4 простых шага: каждый уровень
прогоняется через линейный слой (уравнивание каналов) → всё апсэмплится до 1/4 и
конкатенируется → линейный слой сливает → финальный слой выдаёт класс на пиксель.
Никаких ASPP и тяжёлых модулей. Это работает потому, что трансформерный энкодер
уже даёт большое эффективное рецептивное поле, совмещая локальное и глобальное
внимание. Для сравнения: декодер занимает ~4 % параметров даже у самой большой
модели.

Серия моделей — от **B0** (3,7 млн параметров, для реального времени) до **B5**
(лучшее качество). В этом проекте используется компактная **B0**.

## Данные (CamVid)

Используется CamVid из [CamVid-for-Segmentation](https://github.com/stonewst/CamVid-for-Segmentation),
путь задаётся в `config.py` → `DATA_ROOT`:

```
CamVid/
├── class_palette.csv       # name,r,g,b — цвет каждого из 12 классов (11 + unlabelled)
├── train/  trainannot/     # 367 кадров
├── val/    valannot/       # 101 кадр
└── test/   testannot/      # 233 кадра
```

Картинка — `<stem>.png` (480×360), маска — `<stem>_L.png` (**RGB-изображение**, цвет
кодирует класс). Разбиение 367 / 101 / 233 и 11 классов — те же, что у свёрточной
модели DeepLabV3-ResNet50 (`../Fine_Tuning_DeepLabV3_ResNet50`).

**Важно про маски.** Маски цветные, а модель ждёт индексы классов. Это делает
`camvid_dataset.py`: читает `class_palette.csv`, строит палитру и переводит
RGB-маску в карту индексов. Класс `unlabelled` (`IGNORE_CLASS_NAME` в конфиге)
помечается как `255` и игнорируется и при обучении, и в mIoU. Если маски уже в
индексном формате (grayscale) — поставь `MASK_MODE = "index"`.

## Запуск

Все пути в `config.py` абсолютные (от папки проекта), скрипты можно запускать из любой директории.

```bash
pip install -r requirements.txt

# 1. проверка препроцессинга (ДО обучения):
python3 sanity_check.py
python3 tests/test_mask_mapping.py

# 2. дообучение (сохранит веса и processor в outputs/segformer-b0-camvid):
python3 train.py

# 3. оценка на val и test в исходном разрешении 360×480:
#    mIoU, per-class IoU -> outputs/segformer-b0-camvid/test_metrics.json,
#    лучшие/худшие кадры test -> outputs/predictions
python3 evaluate_model.py                      # итоговые веса
python3 evaluate_model.py <путь к checkpoint>  # любой другой чекпоинт

# 4. предсказание на одной картинке:
python3 predict.py /home/magic/work_task/data/CamVid/test/0001TP_008550.png
```

## Проверка обработки изображений, масок и размера предсказания

Вывод `sanity_check.py` на первом кадре train:

| Этап | Размер |
|---|---|
| исходная картинка / маска | 360×480 (H×W), маска RGB |
| маска → индексы | все цвета маски есть в палитре; `unlabelled` → 255 (4.6 % пикселей кадра) |
| после `SegformerImageProcessor` | `pixel_values` 3×512×512 float, `labels` 512×512 int64 (маска ресайзится nearest, индексы не портятся) |
| логиты модели | 11×128×128 — **1/4 от входа**, не полный размер |
| после `interpolate(bilinear)` | 360×480 = размер исходного кадра |

Тест `tests/test_mask_mapping.py` проверяет нумерацию классов, `unlabelled → 255`,
неизвестный цвет → 255 и обратную раскраску.

## Результаты

Обучение: SegFormer-B0 (`nvidia/mit-b0`), вход 512×512, AdamW lr 6e-5, batch 4,
50 эпох (92 шага на эпоху), аугментации ColorJitter + горизонтальное отражение,
RTX 3050. Итоговые веса — чекпоинт с лучшим mIoU на val (эпоха 36, шаг 3312).

**Метрики считаются в исходном разрешении масок 360×480**: логиты апсэмплятся до
размера кадра и сравниваются с оригинальной маской без ресайза — так же, как у
DeepLabV3. (Во время обучения `Trainer` считает mIoU на масках 512×512, это
используется только для выбора эпохи.)

| Модель | Параметры | Эпохи | mIoU val | mIoU test | Pixel acc. val / test |
|---|---|---|---|---|---|
| DeepLabV3-ResNet50, вся модель, CE + Lovász (свёрточная) | 39.6 млн | 50 | 0.776 | **0.695** | 0.952 / — |
| **SegFormer-B0** | **3.7 млн** | 50 (лучшая 36) | 0.716 | 0.632 | 0.947 / 0.910 |

IoU по классам (test):

| Класс | SegFormer-B0 | DeepLabV3-R50 |
|---|---|---|
| Road | 0.937 | 0.954 |
| Sky | 0.916 | 0.902 |
| Building | 0.826 | 0.837 |
| Car | 0.817 | 0.897 |
| Sidewalk (Pavement) | 0.799 | 0.847 |
| Tree | 0.769 | 0.761 |
| Pedestrian | 0.470 | 0.599 |
| Bicyclist | 0.459 | 0.684 |
| SignSymbol | 0.424 | 0.501 |
| Fence | 0.348 | 0.395 |
| Pole | 0.187 | 0.269 |

**Выводы.**

- SegFormer-B0 в ~11 раз меньше DeepLabV3-ResNet50 и уступает ему 0.06 mIoU на test.
  На крупных классах (дорога, небо, здания, деревья) модели практически равны, а
  разрыв набирается на мелких и редких объектах: велосипедисты (−0.23), пешеходы
  (−0.13), знаки, столбы.
- Причины: у B0 маленькая ёмкость энкодера (32–256 каналов); картинка 480×360
  растягивается в квадрат 512×512 с искажением пропорций; логиты имеют разрешение
  1/4, поэтому тонкие столбы (1–3 пикселя шириной) теряются при билинейном апсэмпле.
  Кроме того, у DeepLabV3 были более сильные аугментации (RandomResizedCrop,
  поворот) и функция потерь Lovász, напрямую оптимизирующая IoU.
- Разрыв val → test (0.716 → 0.632) такой же, как у DeepLabV3 (0.776 → 0.695):
  кадры val из тех же видеопоследовательностей, что и часть train, test — из других.
- С эпохи ~25 mIoU на val почти не растёт (0.70–0.715), loss на val тоже вышел на
  плато — дальнейшее обучение B0 при тех же настройках мало что даст.

**Примеры предсказаний** (`outputs/predictions/`): кадр | эталон | предсказание |
карта ошибок (красный — неверные пиксели, серый — `unlabelled`). Отбор по mIoU
кадра, усреднённому по классам, присутствующим на кадре.

- `best_*.png` — успешные: дорога, тротуар, здания, машины и небо выделены почти
  точно (ошибки ≈ 8 % пикселей), ошибки только на границах объектов и в тонких
  ветвях деревьев на фоне неба.
- `worst_*.png` — ошибочные:
  - `worst_1` (Seq05VD_f02610, 45 % ошибок): основная часть ошибок — крупные области
    дороги и тротуара, где эталон плохо совпадает с видимой геометрией кадра
    (похоже на неточность разметки); дополнительно пропущены столбы и знаки.
  - `worst_2` (12.5 % ошибок, но mIoU кадра 0.37): почти все пиксели верны, низкий
    mIoU даёт тротуар, принятый за дорогу, и мелкие классы (столбы, знаки) —
    на каждом кадре они весят в среднем столько же, сколько дорога.
  - Типичные ошибки: тротуар ↔ дорога, пропуск столбов, знаки и заборы сливаются
    со зданиями.

## Что отдаётся как результат

- Код дообучения (`train.py`) и инференса/оценки (`evaluate_model.py`, `predict.py`).
- Сохранённые веса — `outputs/segformer-b0-camvid/` (`config.json` +
  `model.safetensors` + `preprocessor_config.json`), загружаются через
  `AutoModelForSemanticSegmentation.from_pretrained`.
- Показатели — `outputs/segformer-b0-camvid/test_metrics.json` (mIoU, accuracy,
  per-class IoU для val и test) и примеры в `outputs/predictions/`.

## Замечания по реализации

- Базовая модель `nvidia/mit-b0`: энкодер предобучен на ImageNet, голова декодера
  инициализируется заново под 11 классов CamVid (`ignore_mismatched_sizes=True`).
- `do_reduce_labels=False`: индексы классов мы строим сами, сдвиг меток не нужен.
- SegFormer выдаёт логиты размером **H/4 × W/4** — перед подсчётом mIoU и перед
  визуализацией они билинейно апсэмплятся до размера исходного кадра
  (`nn.functional.interpolate`). Это и есть «восстановление размера предсказания».
- `remove_unused_columns=False` в `TrainingArguments` обязательно, иначе Trainer
  удалит `pixel_values`/`labels`.
- `model.safetensors`, который сохранил `train.py` в конце обучения, не совпал
  побитово с лучшим чекпоинтом (val mIoU 0.707 против 0.716). Он перенесён в
  `outputs/segformer-b0-camvid/superseded/` вместе со своим `val_metrics.json`, а
  итоговыми весами взят `checkpoint-3312` (на test разница 0.6319 против 0.6320).
- Протестировано с `transformers>=4.41` (аргумент `eval_strategy`); для более
  старых версий замени на `evaluation_strategy` в `train.py`.
